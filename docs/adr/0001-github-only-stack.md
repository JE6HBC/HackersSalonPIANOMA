# ADR-0001: GitHubの機能だけで構成する

- **状態:** 採用
- **日付:** 2026-09-22

## 背景

月イチで開く小さなコミュニティイベントの運営システムを作りたい。求めるのは、

- 開催予定とアーカイブの公開
- 参加者の登録管理
- 当日のトーナメント時間管理
- 受賞歴とAI課題のデータベース

一方で制約がある。**運営は少人数で、システム専任はいない。** 月額費用も払いたくない。
そして「イベントの2時間だけ動けばいい」システムのために、常時稼働するサーバを
維持したくない。

利用できるものとして、GitHub Pro の契約がある。

## 決定

**外部サービスを使わず、GitHub の機能だけで構成する。**

| 必要なもの             | GitHubの何を使うか                                                     |
| :--------------------- | :--------------------------------------------------------------------- |
| ホスティング           | GitHub Pages                                                           |
| ビルド・CI             | GitHub Actions                                                         |
| データベース           | リポジトリ内のファイル（→ [ADR-0002](0002-repository-as-database.md)） |
| 管理画面               | Pull Request のレビュー                                                |
| オンライン登録フォーム | Issue Forms + Actions                                                  |
| 権限管理               | リポジトリのコラボレータ設定・CODEOWNERS                               |
| 監査ログ               | Git の履歴                                                             |

## 却下した案

| 案                              | なぜ選ばなかったか                                                                                                                                               |
| :------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vercel + Supabase               | 動くものは速く作れるが、無料枠の条件変更・プロジェクト休止・認証情報の管理が運営の負担になる。月1回2時間のイベントのために常時稼働のDBを持つ割に合わなさが大きい |
| Google Forms + スプレッドシート | 登録は楽だが、データがリポジトリの外に出る。コミュニティからのPRで課題やレポートを育てる、というこのリポジトリの骨格と噛み合わない                               |
| 自前サーバ（VPS）               | 費用と運用。担当者が1人抜けたら止まる                                                                                                                            |
| 静的サイトにせずSPA+外部API     | 結局APIの置き場所が必要になる                                                                                                                                    |

## 結果

**得たもの**

- 費用ゼロ、サーバ運用ゼロ。運営が1人でも止まらない
- 全変更にレビューと履歴が付く（Gitがそのまま監査ログ）
- コントリビューターの入り口がPull Requestに統一される
- 秘密情報をほぼ持たない（＝漏れるものがない）

**失ったもの**（回避策は [architecture.md](../architecture.md) の「できないこと」）

- GitHubアカウントのない人のオンライン登録ができない
- 端末をまたいだリアルタイム同期ができない
- 当日の変更が即座に本番サイトへ反映されない（ビルドに1〜3分）

これらが本当に足りなくなったら、その時点で新しいADRとして外部サービスの導入を提案すること。
**先回りして入れないこと。**
