# ADR-0003: 個人情報を持たない

- **状態:** 採用
- **日付:** 2026-09-22

## 背景

[ADR-0002](0002-repository-as-database.md) により、参加者の情報は**公開リポジトリのファイル**に入る。
Gitは消すのが苦手で、一度公開されたものは他人のクローンにも残る。

一方でイベント運営としては、

- 誰が来たかを記録したい（受賞歴・常連の把握）
- 当日の席決めや、メンターの割り当てに使いたい
- 参加者本人にも「自分の受賞歴」を見せたい

## 決定

**連絡先を一切収集しない。人を指す情報は「表示名」と「GitHubアカウント名」だけにする。**

- 本名を聞かない。受付でも聞かない
- メールアドレス・電話番号・勤務先・住所は、どのフォームにも項目を作らない
- 会場サイネージに参加者一覧を出さない（人数と受賞者のみ）
- `scripts/validate-data.mjs` がメールアドレス・電話番号らしき文字列を検出してCIを落とす

詳細な運用は [docs/policy/privacy.md](../policy/privacy.md)。

## 却下した案

| 案                                         | なぜ選ばなかったか                                               |
| :----------------------------------------- | :--------------------------------------------------------------- |
| 個人情報だけプライベートリポジトリに分ける | リポジトリが2つになり、参照の整合性が取れない。運営の手間も倍    |
| 暗号化してコミットする                     | 鍵の管理が発生する。鍵が漏れた時点で終わりなのは同じ             |
| メールアドレスをハッシュ化して保存         | 総当たりで復元できる。「持っていない」に勝る安全はない           |
| 本名を任意項目にする                       | 任意でも、入れた人の情報は公開される。項目があること自体がリスク |

## 結果

**得たもの**

- 情報漏洩のリスクがほぼ消える（漏れて困るものを持っていない）
- 個人情報保護法まわりの検討が実質不要になる
- 「参加したことを知られたくない」人が安心して来られる
- 削除依頼への対応が軽い（表示名の行を消すだけ）

**失ったもの**

- 参加者への事前連絡ができない（GitHubのIssue経由のみ）
- ドタキャン対策としての連絡手段がない → 定員に余裕を持たせる運用で吸収する
- 同姓同名ならぬ同ハンドルの区別が、GitHubアカウント名がない人については付かない
