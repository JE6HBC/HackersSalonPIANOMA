# 当日運用手順（ランブック）

イベント当日、システム担当が上から順にやることを書いています。
**初めて担当する人が、この文書だけを見て回せること**を目指しています。

前提: 会場スクリーンに繋ぐPCが1台、運営が持つ操作用の端末が1台（同じPCでも可）。

---

## 1週間前

- [ ] `data/events/<日付>/event.json` の `status` が `upcoming` になっているか確認
- [ ] `programs`（タイムテーブル）を確定して埋める
- [ ] 早押しバトルをやるなら `tournament.json` の `rounds` を埋める
  - 各ラウンドの `challengeId` に、出題する課題のIDを入れる
  - 当日まで伏せたい課題は、その課題の front matter を `draft: true` のままにしておく
- [ ] `npm run verify` が通ることを確認してPRをマージ
- [ ] サイト（`/events/<日付>`）に反映されているか目視

## 前日

- [ ] 参加登録Issueから作られたPRをすべて処理する（マージ or クローズ）
- [ ] 登録者数と定員を確認
- [ ] 会場PCで `https://je6hbc.github.io/HackersSalonPIANOMA/signage` が開けるか確認
- [ ] **会場のWi-Fiが不安な場合**は、リポジトリをクローンして `npm run build && npm run preview` で
      ローカル起動できるようにしておく（→「困ったときの逃げ道」）

## 当日：開場前（30分前）

### 1. サイネージを出す

会場PCのブラウザで開く:

```
https://je6hbc.github.io/HackersSalonPIANOMA/signage
```

- 当日の日付に一致するイベントが自動で選ばれます
- 別の回を出したいときは `?event=2026-10-22` を付ける
- **F11 / ⌃⌘F で全画面にする**
- 「NOW」がタイムテーブルと合っているか確認（ブラウザの時計を見ています。PCの時刻がずれていたらそこを直す）

### 2. 運営コンソールを開く

運営が持つ端末のブラウザで開く:

```
https://je6hbc.github.io/HackersSalonPIANOMA/admin
```

- 「対象イベント」が今日の回になっているか確認
- 事前登録者が一覧に出ていることを確認（`committed` と表示される）
- **共用PCを使う場合は、この時点で前回の残りがないか確認する**

## 当日：受付

### 事前登録した人

1. 一覧から名前を探す
2. 「状態」を `checked-in` に変える

### 当日来た人（walk-in）

1. 「参加者を追加」に **表示名** を入れる（**本名は聞かない**）
2. GitHubアカウントがあれば入れてもらう（任意）
3. 「追加してチェックイン」を押す

> 入力内容はこの端末のブラウザにだけ保存されます。サーバには送られません。
> 本名・メールアドレス・電話番号は入力しないこと（[個人情報の取り扱い方針](policy/privacy.md)）。

## 当日：トーナメント（早押しバトル）

### 準備

操作端末で開く:

```
https://je6hbc.github.io/HackersSalonPIANOMA/signage/timer
```

1. 「トーナメント」で今日の回を選ぶ
2. 「ラウンド」で第1ラウンドを選ぶ
3. **「表示用ウィンドウ」ボタン**を押すと、操作UIのない表示専用ウィンドウが開く
   → これを会場スクリーン側に移して全画面にする
   → 操作ウィンドウと表示ウィンドウは自動で同期します（**同じPCの同じブラウザである必要があります**）

### 進行

| 操作                               | ボタン      | キーボード       |
| :--------------------------------- | :---------- | :--------------- |
| 開始 / 一時停止                    | 開始        | <kbd>Space</kbd> |
| 次のラウンド（休憩があれば休憩へ） | 次へ        | <kbd>N</kbd>     |
| ひとつ戻る                         | 前へ        | —                |
| 今のラウンドを最初から             | リセット    | <kbd>R</kbd>     |
| 時間を足す / 減らす                | +1分 / -1分 | —                |
| 全画面                             | —           | <kbd>F</kbd>     |

- 残り30秒で画面が赤くなります
- 0になると音が鳴って自動停止します
  （**音が出ない場合**: 一度「開始」を押すまでブラウザは音を鳴らせません。仕様です）

### 結果を記録する

`/admin` の「受賞を記録する」で、賞と受賞者を選ぶと `results.json` の1行分が生成されます。
コピーしておいて、後で貼り付けます。その場でリポジトリに入れる必要はありません。

## 翌日以降：リポジトリへ反映

```bash
git switch -c event/<日付>-results

# 1. participants.json を書き出したファイルで置き換える
# 2. results.json に受賞を貼る
# 3. event.json の status を archived にする
# 4. report.md に開催レポートを書く
# 5. 出題した課題の usedIn に日付を足す / draft を false にする

npm run verify
git add data/
git commit -m "chore(data): <日付> の開催記録を追加"
git push -u origin event/<日付>-results
gh pr create
```

マージするとGitHub Pagesが自動で更新され、アーカイブ・殿堂・課題DBに反映されます。

## 困ったときの逃げ道

**原則: イベントを止めない。データは後から直せる。**

| 症状                                 | その場での対処                                                                                                                                                     |
| :----------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会場のネットが落ちた                 | リポジトリをクローン済みのPCで `npm run build && npm run preview`。`http://localhost:4321/HackersSalonPIANOMA/` がそのまま使えます                                 |
| タイマーが表示ウィンドウと同期しない | 別のブラウザ・別のPCで開いていませんか。同期は同一ブラウザ内だけです。揃わないときは表示ウィンドウ側を直接操作してください（操作UIは `?display=1` を消せば出ます） |
| タイマーの残り時間がおかしい         | 「リセット」でそのラウンドの頭に戻ります。それでも変なら「+1分 / -1分」で手動調整。最悪、スマホのタイマーでも進行はできます                                        |
| サイネージの「NOW」がずれている      | PCの時刻を確認。タイムテーブル自体が違う場合は、当日は放置してイベント後にPRで直す                                                                                 |
| 登録画面に何も出ない                 | ブラウザのプライベートモードでは保存できません。通常ウィンドウで開き直してください                                                                                 |
| 誤って「破棄」を押した               | 書き出し前なら復旧できません。紙とペンに切り替えて、後から入力してください                                                                                         |
| 参加者が個人情報を入力してしまった   | その場で削除。すでにPRになっている場合はマージせずクローズ                                                                                                         |

**「後でPRで直す」が使える場面では、当日は必ずそちらを選んでください。**
イベント中にリポジトリを直接いじらないこと。
