# 個人情報の取り扱い方針

**このリポジトリは公開されています。** ここに書いたものは、誰でも読めて、誰でもクローンでき、
検索エンジンにも載ります。一度公開したものは、消しても取り戻せないと考えてください。

そのうえで、このイベントは参加者の記録（誰が来て、誰が何を受賞したか）を残したい。
この2つを両立させるためのルールが、この文書です。

---

## 原則

### 1. 収集しない

最も安全な個人情報は、そもそも持っていない情報です。
このシステムは **参加者の連絡先を一切持ちません。** 当日の連絡はその場で、事前の連絡はGitHub上で行います。

### 2. リポジトリに入れてよいもの / だめなもの

| 入れてよい                       | だめ                                             |
| :------------------------------- | :----------------------------------------------- |
| 表示名・ハンドル・ニックネーム   | 本名（本人が表示名として本名を選んだ場合を除く） |
| GitHubアカウント名               | メールアドレス                                   |
| 本人が公開を希望した所属・肩書き | 電話番号・SNSのDM先                              |
| 興味のある技術分野               | 勤務先・部署（本人の希望がない限り）             |
| 受賞歴・LT登壇歴                 | 住所・年齢・顔写真                               |
| 参加した回                       | 業務内容の具体的な記述                           |

**判断に迷ったら入れない。** 後から足すのは簡単ですが、消すのは実質不可能です。

### 3. 本名を要求しない

当日の受付でも、オンライン登録でも、本名を聞きません。
「ゆき」「@je6hbc」「後ろの席の人」で運営は回ります。

## 具体的な場面ごとの扱い

### オンライン事前登録（GitHub Issue）

- 入力してもらうのは **表示名・興味・LT希望** のみ
- GitHubアカウント名はIssueの投稿者から自動で取得する（別途入力させない）
- 取り込み時に文字種と長さを制限する。メールアドレスが書かれていても保存されない
- 反映はPull Request経由。**マージ前に運営が中身を目で見る**

### 当日の会場登録（運営コンソール `/admin`）

- 入力内容はその端末の `localStorage` にしか残らない。サーバには送られない
- イベント後、`participants.json` を書き出してPRにする。このとき運営が中身を確認する
- **会場の共用PCを使った場合、イベント後に「この端末の追加分を破棄」を押す**

### 会場サイネージ（`/signage`）

大画面に映るのは以下だけです。

- 表示名（受賞表示・LT登壇者として）
- 登録者数・チェックイン数（人数のみ）
- 卓の名前と席数

**参加者の一覧を大画面に出しません。** 来ていることを他人に知られたくない人がいるためです。

### 写真・SNS

- 会場での撮影は、写り込む人の同意を取ってから
- リポジトリに人物が写った画像を追加しないでください（会場・ピアノ・スクリーンのみ可）

## 削除の依頼

自分の記録を消したい場合、次のどれでも構いません。

1. Issueを立てる（「[削除依頼] 表示名 〇〇」）
2. 該当ファイルを直接編集するPull Requestを出す
3. オーナー [@JE6HBC](https://github.com/JE6HBC) に直接連絡する

**理由は聞きません。** 依頼があれば、該当する `participants.json` と `results.json` の行を削除します。

ただし正直に書いておくと、Gitの履歴からは完全には消えません。
履歴ごと消す（force push）ことは技術的には可能ですが、他の人のクローンには残ります。
表示名しか記録していないのは、この「消せなさ」を前提にしているからです。

## 技術的な担保

- `npm run validate:data` が `data/` 配下のJSONとfront matterを走査し、
  メールアドレス・電話番号らしき文字列を検出したらCIを落とす
- 検出パターンは `scripts/validate-data.mjs` の `PII_PATTERNS`
- Markdown本文（AI課題の問題文）は、例としてメールアドレスが登場しうるため検査対象外。
  ただし **実在の連絡先を例に使わないこと**（`example.com` を使う）

この自動チェックは最後の砦であって、最初の砦ではありません。
書く前に気をつけるのが本体です。
