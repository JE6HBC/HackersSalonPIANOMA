# ロードマップ

「次に何をやるといいか」の置き場です。決定事項ではなく**叩き台**なので、
順番を入れ替える提案も歓迎します。着手するときはIssueを立ててから。

## いまの状態（v0.1 — 土台）

- [x] リポジトリ構造とコントリビューションのルール
- [x] データスキーマ（イベント・参加者・卓・トーナメント・受賞・AI課題）
- [x] 公開サイト（トップ・開催一覧・詳細・課題DB・殿堂）
- [x] 会場サイネージ（現在のプログラム・卓・人数）
- [x] トーナメントタイマー（ラウンド・休憩・表示用ウィンドウ）
- [x] 運営コンソール（当日登録・チェックイン・JSON書き出し）
- [x] CI（整形・データ整合性・型・ビルド）とGitHub Pagesへの自動デプロイ
- [x] 参加登録Issue → 自動PR

## 次（v0.2 — 実戦投入で困ったところを直す）

1回イベントで使ってから決める、が原則。想定している候補:

- [ ] **参加登録のQRコード表示** — 会場で登録URLを読ませたい。依存を増やさずSVGで生成できるか
- [ ] **サイネージの卓に「今そこにいる人数」を出す** — 運営コンソールから卓に割り当てる
- [ ] **タイマーの音のバリエーション** — 残り1分の予告音、終了音の選択
- [ ] **課題DBの検索** — 現状はレベル/カテゴリのフィルタのみ。全文検索が要るか要検討
- [ ] **開催レポートのテンプレ強化** — 写真なしで雰囲気が伝わる書き方の型

## その先（v0.3以降 — 必要になったら）

- [ ] **早押しの回答提出** — 現状は口頭・挙手。提出をシステムで受けるならサーバが要る（[ADR-0001](adr/0001-github-only-stack.md) の見直し）
- [ ] **参加者のマイページ** — 自分の受賞歴。GitHubアカウント単位の静的ページなら今の構成でも作れる
- [ ] **課題の自動採点** — 入出力が決まっている課題なら、Actionsで回せる可能性がある
- [ ] **多言語対応** — 英語話者の参加が増えたら

## やらないと決めていること

- 参加者の連絡先を持つこと（[ADR-0003](adr/0003-no-personal-data.md)）
- 端末をまたいだリアルタイム同期（[ADR-0004](adr/0004-event-day-state-in-browser.md)）
- 必要になる前に外部サービスを入れること（[ADR-0001](adr/0001-github-only-stack.md)）
